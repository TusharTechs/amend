Amend turns a regulatory change into a pull request that is proven to implement it. It reads the official redline clause by clause, finds where the change lands in the code, drives the fix through IBM Bob, and proves every fix with a test that fails before the change and passes after.

How it works

Eight stages, most of them without a model

  1. Redline. Point-in-time versions from the eCFR API, diffed clause by clause; renumbered clauses separated from real amendments.deterministic
  2. Obligations. Drafted by the agent; any quote not verbatim in the law is rejected; a named human approves.agent + validator
  3. Impact. A code graph of routes, router dependencies, mounts, SQL-view alias lineage and sinks.deterministic
  4. Remediate. Test first, proven to fail on the base commit, then the fix.agent
  5. Audit. A read-only auditor and a canary sweep that plants a synthetic customer and searches every store.deterministic sweep
  6. Prove. Fail-before/pass-after, locked pre-existing tests, regression suite.deterministic
  7. Evidence. Traceability matrix and a graded certificate. Never "compliant".deterministic
  8. Guard. The same checks as a merge gate in GitHub Actions and a Bob lifecycle hook, citing the clause.0 Bobcoins

Architecture

Bob is where every run starts

The /amend command hands the work to amend-lead, which moves through four custom modes with enforced separation of duties. Each mode calls Amend's MCP server for facts; the deterministic engine behind it does the analysis and the proof. Hooks gate every edit, and the same guard runs again in CI.

IBM Bob

Amend runs inside Bob

Amend ships as a Bob pack: five custom modes with enforced separation of duties (the auditor cannot edit; the fixer can edit only app code and new compliance tests), five skills, rules that treat regulation text and code comments as data, an MCP server with eleven tools that give Bob facts it cannot invent, and lifecycle hooks that block edits to locked tests and run the guard after every edit. IBM Bob also built Amend's engine, demo app, MCP server, hooks and pack; the sessions are in the repository.

IBM watsonx.ai

Granite proposes. Amend checks.

Two MCP tools call IBM Granite 4 on watsonx.ai. screen_untrusted_text reads every code comment and docstring a coding agent will see and flags text aimed at AI agents: on Lendwise it flags exactly one of 48, the planted NOTE TO AI AGENTS comment, in 3 of 3 runs. draft_obligations drafts obligations from the verbatim clause text, never from memory, and every draft goes through the same verbatim-quote validator and human approval as a person's: 15 drafts from the 2024 amendment, 15 verbatim quotes. Asked from memory, the same model described an unrelated antitrust rule, which is why Amend grounds it.
